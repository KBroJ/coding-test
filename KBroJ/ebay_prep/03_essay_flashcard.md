# 서술형 플래시카드
> Q 보고 A 떠올리기 연습용 / 시험장 직전 암기용

---

## 사용법
1. Q만 보고 A를 입으로 말해보기
2. 키워드 위주로 체크 (모두 외울 필요 없음)
3. 시험에서: 정의 → 특징/차이 → 사용처 순으로 작성

---

## Card 1: TCP vs UDP ← 데모 문제 유형

**Q: TCP와 UDP의 차이점과 각각의 사용처는?**

<details>
<summary>A 보기</summary>

**TCP** - **연결 지향**, **신뢰성 높음**, **순서 보장**, 느림
- 3-way handshake로 연결 수립 후 전송
- 손실 패킷 재전송, 순서 보장
- 사용처: **HTTP/HTTPS**, 파일전송(FTP), 이메일(SMTP), DB 연결

**UDP** - **비연결형**, **신뢰성 낮음**, **빠름**
- 연결 없이 바로 전송, 재전송 없음
- 사용처: **실시간 스트리밍**, **온라인 게임**, DNS 조회, VoIP

> 핵심 키워드: 연결지향 / 비연결형 / 신뢰성 / 속도 / 재전송

</details>

---

## Card 2: HTTP vs HTTPS

**Q: HTTP와 HTTPS의 차이점과 HTTPS를 사용하는 이유는?**

<details>
<summary>A 보기</summary>

**HTTP** - **암호화 없음**, 평문 전송, 빠름
- 중간에 데이터 탈취 위험 (스니핑)

**HTTPS** - **SSL/TLS 암호화**, 느림 (암호화 오버헤드)
- 데이터 **도청, 변조 방지**
- 사용처: 로그인, 결제, 개인정보 처리 → **보안 필요한 모든 곳**

> 핵심 키워드: 암호화 / SSL/TLS / 도청방지 / 보안

</details>

---

## Card 3: REST API

**Q: REST API란 무엇이고, HTTP 메서드 종류와 역할은?**

<details>
<summary>A 보기</summary>

**REST API** - HTTP 기반으로 **자원(Resource)을 URI로 표현**하고, **HTTP 메서드로 행위 정의**하는 API 설계 방식

| 메서드 | 역할 | 예시 |
|--------|------|------|
| **GET** | 조회 | GET /users/1 |
| **POST** | 생성 | POST /users |
| **PUT** | 전체 수정 | PUT /users/1 |
| **PATCH** | 부분 수정 | PATCH /users/1 |
| **DELETE** | 삭제 | DELETE /users/1 |

특징: **무상태성(Stateless)** - 서버가 클라이언트 상태 저장 안 함 → 확장성 좋음

> 핵심 키워드: URI/자원 / HTTP메서드 / 무상태(Stateless)

</details>

## Card 4: 프로세스 vs 스레드

**Q: 프로세스와 스레드의 차이점은?**

<details>
<summary>A 보기</summary>

**프로세스** - **독립적인 메모리 공간** 할당받는 실행 단위
- 한 프로세스 오류가 **다른 프로세스에 영향 없음**
- 무거움, 생성 비용 큼

**스레드** - 프로세스 내 실행 단위, **메모리 공유**
- 같은 프로세스 스레드끼리 힙/코드/데이터 공유
- 빠르고 가볍지만 **Race Condition(동기화 문제)** 발생 가능

요약:
- 프로세스: 독립 메모리, 안전, 무거움
- 스레드: 공유 메모리, 빠름, 동기화 필요

> 핵심 키워드: 독립 메모리 / 공유 메모리 / Race Condition / 동기화

</details>

## Card 5: 데드락(Deadlock)

**Q: 데드락이란 무엇이고, 발생 조건과 해결법은?**

<details>
<summary>A 보기</summary>

**데드락** - 두 개 이상의 프로세스/스레드가 **서로 상대방이 가진 자원을 기다리며 무한 대기**하는 상태

발생 예시:
- 스레드 A가 자원1을 갖고 자원2를 대기
- 스레드 B가 자원2를 갖고 자원1을 대기
- → 영원히 기다림

발생 4가지 조건 (모두 만족해야 발생):
1. **상호 배제** - 자원을 혼자 점유
2. **점유 대기** - 자원 갖고 다른 자원 대기
3. **비선점** - 강제로 자원 뺏을 수 없음
4. **순환 대기** - 순환 형태로 대기

해결법:
- 자원 획득 순서 통일 (순환 대기 제거)
- 타임아웃 설정 후 해제

> 핵심 키워드: 상호 대기 / 4가지 조건 / 순환 대기

</details>

## Card 6: 데이터베이스 인덱스

**Q: DB 인덱스란 무엇이고, 장단점과 적합한 사용 상황은?**

<details>
<summary>A 보기</summary>

**인덱스** - 특정 컬럼의 **검색 속도를 높이는 자료구조** (책의 목차와 같은 역할)

장점:
- SELECT 성능 향상 (O(N) → O(log N))

단점:
- **INSERT/UPDATE/DELETE 느려짐** (인덱스도 함께 수정)
- 추가 **저장 공간** 필요

적합한 상황:
- **조회가 잦고 수정이 적은** 컬럼
- 예: 사용자 ID, 이메일, 생성일

> 핵심 키워드: 검색 속도 / O(log N) / 쓰기 느려짐 / 조회 위주 컬럼

</details>

---

## Card 7: 트랜잭션 & ACID

**Q: 트랜잭션이란 무엇이고, ACID 4가지 특성은?**

<details>
<summary>A 보기</summary>

**트랜잭션** - DB에서 **하나의 논리적 작업 단위** (예: 계좌 이체)

**ACID**:
- **A**tomicity (원자성): **전부 성공 or 전부 실패** (중간 상태 없음)
- **C**onsistency (일관성): 트랜잭션 전후로 **무결성 유지**
- **I**solation (격리성): 동시 실행 트랜잭션이 **서로 영향 X**
- **D**urability (지속성): 커밋된 결과는 **영구 반영**

> 핵심 키워드: 논리적 작업 단위 / A원자 / C일관 / I격리 / D지속

</details>

## Card 8: 스택 vs 큐

**Q: 스택과 큐의 차이점과 각각의 사용처는?**

<details>
<summary>A 보기</summary>

**스택(Stack)** - **LIFO** (Last In First Out, 후입선출)
- 마지막에 넣은 것이 먼저 나옴
- 사용처: 함수 호출 스택, **브라우저 뒤로가기**, 괄호 검사, **Undo**

**큐(Queue)** - **FIFO** (First In First Out, 선입선출)
- 먼저 넣은 것이 먼저 나옴
- 사용처: **작업 대기열**, 이벤트 처리, **BFS 탐색**, 메시지 큐

> 핵심 키워드: LIFO(스택) / FIFO(큐) / 뒤로가기/Undo / BFS/대기열

</details>

## 시험장 직전 핵심어 암기 (1분 복기)

```
TCP: 연결지향, 신뢰성, 순서보장, HTTP/FTP/이메일
UDP: 비연결, 빠름, 스트리밍/게임/DNS

HTTP: 평문, 빠름
HTTPS: SSL/TLS 암호화, 보안

REST: URI=자원, 메서드=행위, 무상태
GET조회 / POST생성 / PUT전체수정 / DELETE삭제

프로세스: 독립메모리, 안전
스레드: 공유메모리, 빠름, Race Condition

데드락: 상호대기, 4조건(상호배제/점유대기/비선점/순환대기)

인덱스: O(logN)검색, 쓰기느림, 조회위주컬럼에 사용

트랜잭션: 논리적 작업단위
ACID: A원자성 / C일관성 / I격리성 / D지속성

스택: LIFO, 뒤로가기/Undo/괄호검사
큐: FIFO, BFS/대기열
```
