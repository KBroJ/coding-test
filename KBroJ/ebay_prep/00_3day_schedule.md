## 시험 당일 전략

### 문제 확인 순서 (처음 5분)
```
1. 알고리즘 문제 → 입력 타입, return 타입, N 크기 확인
2. SQL 문제 → 테이블 구조, 출력 컬럼명 확인
3. 서술형 주제 → 아는 주제인지 확인
→ 어떤 것부터 풀지 결정 (보통 SQL → 에세이 → 알고리즘 순 or 알고 먼저)
```

### 알고리즘 (80분)
```
0~5분:   문제 읽기 + 유형 파악 (N 크기 → 알고리즘 선택)
5~15분:  손으로 예제 풀어보기 + 로직 설계
15~70분: 구현
70~80분: 예제 테스트 + 엣지 케이스 확인
```

- 막히면 50분에 완전탐색이라도 제출 → 부분 점수 확보
- 제약조건 없으면 N ≤ 100 가정하고 O(N²)으로 먼저 짜기

### SQL (30분)
```
0~3분:  테이블 구조 파악 + 출력 컬럼명 확인
3~20분: 쿼리 작성
20~25분: 테스트 실행
25~30분: 컬럼명/정렬 방향 재확인 후 제출
```

### 서술형 (30분)
```
0~5분:  키워드 메모 (정의, 특징, 사용처)
5~25분: 작성 (정의 → 특징/차이 → 사용처 순)
25~30분: 검토
```

## 긴급 플랜 (막혔을 때)

```
알고리즘 막혔을 때:
1. 완전탐색으로 일단 짜기 → 일부 TC 통과라도

3. 50분 지나면 미련 없이 제출하고 SQL로 이동

1. GROUP BY + SUM 기본 패턴으로 일단 작성

3. 20분 지나면 제출하고 에세이로 이동
```
