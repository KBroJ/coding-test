### Card 1: TCP vs UDP ★★★ (최빈출)

**Q: TCP와 UDP의 차이점과 각각의 사용처를 설명하시오.**

**키워드 힌트**
```
TCP: 연결지향 / 3-way handshake / 신뢰성 / 순서보장 / 재전송 / 느림
UDP: 비연결형 / 신뢰성X / 빠름 / 스트리밍/게임/DNS
```

<details>
<summary>답안 예시 (시험 작성 분량)</summary>

TCP(Transmission Control Protocol)는 연결 지향 프로토콜로, 데이터 전송 전에 3-way handshake를 통해 연결을 먼저 수립합니다. 3-way handshake는 ① 클라이언트가 SYN을 보내고, ② 서버가 SYN-ACK로 응답하며, ③ 클라이언트가 ACK를 보내는 3단계로 이루어집니다. TCP는 패킷의 순서를 보장하고 손실된 패킷을 재전송하므로 신뢰성이 높지만, 이 과정에서 오버헤드가 발생해 속도가 느립니다. 신뢰성이 중요한 HTTP/HTTPS, 파일 전송(FTP), 이메일(SMTP) 등에 사용됩니다.

UDP(User Datagram Protocol)는 비연결형 프로토콜로, 연결 수립 없이 데이터를 바로 전송합니다. 순서 보장이나 재전송이 없어 신뢰성은 낮지만 속도가 빠릅니다. 일부 데이터 손실이 허용되는 실시간 스트리밍, 온라인 게임, DNS 조회, VoIP 등에 사용됩니다.

</details>

### Card 2: HTTP vs HTTPS ★★

**Q: HTTP와 HTTPS의 차이를 설명하고, HTTPS가 필요한 이유를 서술하시오.**

**키워드 힌트**
```
HTTP: 평문 / 암호화X / 빠름 / 도청위험
HTTPS: SSL/TLS / 암호화 / 인증서 / 도청·변조 방지
```

<details>
<summary>답안 예시</summary>

HTTP(HyperText Transfer Protocol)는 데이터를 암호화 없이 평문으로 전송하는 프로토콜입니다. 속도가 빠르지만 중간자 공격(MITM)으로 데이터가 도청되거나 변조될 위험이 있습니다.

HTTPS(HTTP Secure)는 SSL/TLS 프로토콜을 통해 데이터를 암호화하여 전송합니다. 클라이언트와 서버는 TLS Handshake를 통해 암호화 방식을 협의하고 키를 교환한 후 통신합니다. 이를 통해 도청, 변조, 위장을 방지합니다. 암호화 오버헤드로 HTTP보다 약간 느리지만, 로그인, 결제, 개인정보 처리 등 보안이 중요한 모든 웹 서비스에서 HTTPS 사용이 필수입니다.

</details>

### Card 3: OSI 7계층 ★★

**Q: OSI 7계층 모델을 설명하고 각 계층의 역할과 대표 프로토콜을 서술하시오.**

**키워드 힌트**
```
암기: 물-데-네-전-세-표-응
IP = 3계층(네트워크)
TCP·UDP = 4계층(전송)
HTTP·FTP·DNS = 7계층(응용)
```

<details>
<summary>답안 예시</summary>

OSI 7계층은 네트워크 통신을 7단계로 나눈 표준 참조 모델입니다.

1계층 **물리(Physical)**: 전기 신호, 비트 전송 (케이블, 허브)
2계층 **데이터링크(Data Link)**: 같은 네트워크 내 노드 간 전송, MAC 주소 사용 (이더넷, 스위치)
3계층 **네트워크(Network)**: 서로 다른 네트워크 간 라우팅, IP 주소 사용 (IP 프로토콜, 라우터)
4계층 **전송(Transport)**: 종단 간 신뢰성 있는 데이터 전송, 포트 번호 사용 (TCP, UDP)
5계층 **세션(Session)**: 연결 수립·유지·종료 관리
6계층 **표현(Presentation)**: 데이터 암호화, 압축, 인코딩 변환 (JPEG, ASCII)
7계층 **응용(Application)**: 사용자와 가장 가까운 계층, 애플리케이션 서비스 (HTTP, FTP, DNS, SMTP)

실제 인터넷에서는 TCP/IP 4계층 모델(링크 → 인터넷 → 전송 → 응용)을 주로 사용합니다.

</details>

### Card 4: REST API ★★

**Q: REST API의 개념과 HTTP 메서드의 종류 및 역할을 설명하시오.**

**키워드 힌트**
```
URI=자원 / 메서드=행위 / 무상태(Stateless)
GET조회 / POST생성 / PUT전체수정 / PATCH부분수정 / DELETE삭제
멱등성: GET·PUT·DELETE는 멱등 / POST·PATCH는 비멱등
```

<details>
<summary>답안 예시</summary>

REST(Representational State Transfer)는 HTTP를 기반으로 자원(Resource)을 URI로 표현하고, HTTP 메서드로 해당 자원에 대한 행위를 정의하는 API 설계 원칙입니다.

주요 HTTP 메서드는 다음과 같습니다. GET은 자원 조회, POST는 자원 생성, PUT은 자원 전체 수정, PATCH는 자원 일부 수정, DELETE는 자원 삭제에 사용됩니다. 멱등성(같은 요청을 여러 번 해도 결과가 동일한 성질) 측면에서 GET, PUT, DELETE는 멱등하지만 POST는 멱등하지 않습니다.

REST의 핵심 특징은 무상태성(Stateless)으로, 서버가 클라이언트의 이전 요청 상태를 저장하지 않아 서버 확장이 용이합니다. RESTful한 설계에서는 `/users/{id}`처럼 명사형 URI를 사용하고, 행위는 메서드로 표현합니다.

</details>

### Card 5: 쿠키 vs 세션 vs JWT ★★

**Q: 쿠키, 세션, JWT의 차이점과 각각의 장단점을 설명하시오.**

**키워드 힌트**
```
HTTP는 stateless → 상태 유지 필요
쿠키: 클라이언트 저장 / 보안 취약
세션: 서버 저장 / 서버 부하
JWT: 토큰 자체에 정보 포함 / 탈취 시 만료 전 무효화 어려움
```

<details>
<summary>답안 예시</summary>

HTTP는 무상태(Stateless) 프로토콜이라 로그인 상태 같은 정보를 유지하려면 별도 수단이 필요합니다.

**쿠키**는 클라이언트(브라우저)에 데이터를 저장하는 작은 파일입니다. 서버 부하가 없지만, 클라이언트에 저장되므로 보안에 취약하고 조작될 위험이 있습니다.

**세션**은 인증 정보를 서버에 저장하고, 클라이언트에는 세션 ID만 쿠키로 전달합니다. 보안은 좋지만 서버 메모리를 사용하므로 사용자가 많아지면 부하가 증가합니다.

**JWT(JSON Web Token)**는 인증 정보를 토큰 자체에 담아 클라이언트에 저장합니다. 서버에 저장 공간이 필요 없어 확장성이 뛰어납니다. 단, 토큰이 탈취되면 만료 전까지 무효화하기 어렵다는 단점이 있어, 짧은 만료시간과 리프레시 토큰을 함께 사용하는 방식으로 보완합니다.

</details>

### Card 6: 프로세스 vs 스레드 ★★★

**Q: 프로세스와 스레드의 차이를 메모리 구조 관점에서 설명하시오.**

**키워드 힌트**
```
프로세스: 독립 메모리(코드+데이터+힙+스택 각자 보유) / 안전 / 무거움
스레드: 코드+데이터+힙 공유, 스택만 별도 / 빠름 / Race Condition
컨텍스트 스위칭: 프로세스 > 스레드 비용
```

<details>
<summary>답안 예시</summary>

프로세스는 운영체제로부터 독립적인 메모리 공간(코드, 데이터, 힙, 스택)을 할당받아 실행되는 프로그램의 단위입니다. 각 프로세스는 완전히 독립된 메모리를 사용하므로, 한 프로세스의 오류가 다른 프로세스에 영향을 주지 않습니다. 대신 프로세스 간 통신(IPC)이 필요하고 컨텍스트 스위칭 비용이 큽니다.

스레드는 프로세스 내에서 실행되는 더 작은 실행 단위입니다. 같은 프로세스의 스레드들은 코드, 데이터, 힙 영역을 공유하고, 스택만 각자 따로 가집니다. 메모리를 공유하므로 통신이 빠르고 생성 비용이 낮지만, 여러 스레드가 동시에 공유 자원에 접근할 때 Race Condition(경쟁 상태)이 발생할 수 있어 동기화가 필요합니다.

</details>

### Card 7: 교착상태(Deadlock) ★★

**Q: 교착상태의 개념, 발생 4가지 조건, 해결 방법을 설명하시오.**

**키워드 힌트**
```
발생 4조건: 상호배제 / 점유대기 / 비선점 / 순환대기 (모두 동시 충족시 발생)
해결: 조건 하나 제거 / 타임아웃 / 자원 순서 통일
```

<details>
<summary>답안 예시</summary>

교착상태(Deadlock)는 두 개 이상의 프로세스가 서로 상대방이 점유한 자원을 기다리며 무한히 대기하는 상태입니다.

발생 4가지 조건은 다음과 같으며, 모두 동시에 충족될 때 발생합니다. ① 상호 배제: 한 번에 한 프로세스만 자원 사용 가능, ② 점유 대기: 자원을 점유한 채 다른 자원을 대기, ③ 비선점: 다른 프로세스의 자원을 강제로 빼앗을 수 없음, ④ 순환 대기: A→B→C→A처럼 순환 형태로 자원을 대기.

해결 방법으로는 4가지 조건 중 하나를 제거하는 예방, 안전한 상태에서만 자원을 할당하는 회피(은행원 알고리즘), 발생 후 탐지해서 복구하는 방법이 있습니다. 실무에서는 자원 획득 순서를 통일하거나 타임아웃을 설정하는 방식을 주로 사용합니다.

</details>

### Card 8: 동기화 - Mutex vs Semaphore ★

**Q: Mutex와 Semaphore의 차이점을 설명하시오.**

**키워드 힌트**
```
공통: Race Condition 방지 (공유 자원 동시 접근 제어)
Mutex: 1개 스레드만 / 잠금 획득자만 해제 / 화장실 열쇠 1개
Semaphore: N개까지 허용 / 누구든 해제 가능 / 주차장 N자리
```

<details>
<summary>답안 예시</summary>

Mutex와 Semaphore는 모두 여러 스레드가 공유 자원에 동시 접근하는 Race Condition을 방지하기 위한 동기화 도구입니다.

Mutex(Mutual Exclusion)는 한 번에 하나의 스레드만 공유 자원에 접근할 수 있도록 잠금을 제공합니다. 잠금을 획득한 스레드만 잠금을 해제할 수 있습니다. 화장실 열쇠가 하나인 것과 같은 개념입니다.

Semaphore는 동시에 접근할 수 있는 스레드 수를 N개로 제한하는 카운팅 방식입니다. 잠금을 획득하지 않은 다른 스레드도 해제할 수 있어 Mutex보다 유연합니다. 주차장에 N개의 자리가 있는 것과 같은 개념으로, 이진 세마포어(N=1)는 Mutex와 유사하게 동작합니다.

</details>

### Card 9: 컨텍스트 스위칭 ★

**Q: 컨텍스트 스위칭이란 무엇이고, 스레드가 프로세스보다 비용이 낮은 이유는?**

**키워드 힌트**
```
CPU가 실행 중인 프로세스/스레드 전환
PCB에 현재 상태 저장 → 다음 것 복구
스레드: 메모리 공유 → 캐시 유지 → 비용 낮음
```

<details>
<summary>답안 예시</summary>

컨텍스트 스위칭은 CPU가 현재 실행 중인 프로세스(또는 스레드)를 중단하고 다른 프로세스(또는 스레드)로 전환하는 과정입니다. 이때 현재 상태(레지스터, 프로그램 카운터 등)를 PCB(Process Control Block)에 저장하고, 다음에 실행할 프로세스의 상태를 복구합니다.

스레드의 컨텍스트 스위칭이 프로세스보다 비용이 낮은 이유는, 스레드는 같은 프로세스 내에서 코드·데이터·힙 메모리를 공유하기 때문입니다. 프로세스 간 전환은 메모리 주소 공간 자체가 바뀌어 CPU 캐시를 무효화해야 하지만, 스레드 간 전환은 스택과 레지스터만 교체하면 되어 캐시를 재활용할 수 있습니다.

</details>

### Card 10: 트랜잭션과 ACID ★★★

**Q: 트랜잭션의 개념과 ACID 4가지 특성을 설명하시오.**

**키워드 힌트**
```
트랜잭션: 논리적 작업 단위 (계좌이체 예시)
A원자성: 전부성공 or 전부실패
C일관성: 무결성 유지
I격리성: 트랜잭션 간 독립
D지속성: 커밋 후 영구 반영
```

<details>
<summary>답안 예시</summary>

트랜잭션은 데이터베이스에서 하나의 논리적 작업 단위입니다. 예를 들어 A가 B에게 돈을 이체할 때 "A 잔고 감소"와 "B 잔고 증가"는 반드시 함께 성공하거나 함께 실패해야 합니다.

트랜잭션의 4가지 특성(ACID)은 다음과 같습니다. **원자성(Atomicity)**은 트랜잭션의 모든 작업이 전부 성공하거나 전부 실패해야 하며, 중간 상태가 없어야 합니다. **일관성(Consistency)**은 트랜잭션 전후로 데이터베이스의 무결성 제약 조건이 항상 유지되어야 합니다. **격리성(Isolation)**은 동시에 실행되는 트랜잭션들이 서로 영향을 주지 않아야 합니다. **지속성(Durability)**은 커밋된 트랜잭션의 결과는 시스템 장애가 발생해도 영구적으로 반영되어야 합니다.

</details>

### Card 11: DB 인덱스 ★★

**Q: 데이터베이스 인덱스의 개념, 장단점, 적합한 사용 상황을 설명하시오.**

**키워드 힌트**
```
책 목차 역할 / B-tree 구조 / O(logN) 탐색
장점: SELECT 빠름
단점: INSERT/UPDATE/DELETE 느림 / 저장공간 추가
적합: 조회 잦고 수정 적은 컬럼 (PK, 이메일, 생성일)
```

<details>
<summary>답안 예시</summary>

인덱스는 데이터베이스에서 특정 컬럼의 검색 속도를 높이기 위한 자료구조로, 책의 목차와 같은 역할을 합니다. 내부적으로 B-tree 구조를 사용하여 O(log N)의 빠른 탐색이 가능합니다.

장점은 SELECT 쿼리 성능이 크게 향상된다는 점입니다(전체 스캔 O(N) → 인덱스 탐색 O(log N)). 단점으로는 INSERT, UPDATE, DELETE 시 인덱스도 함께 수정해야 하므로 쓰기 성능이 저하되고, 추가 저장 공간이 필요합니다.

따라서 **조회가 잦고 수정이 적은 컬럼**(사용자 ID, 이메일, 생성일 등)에 적용하는 것이 적합합니다. 반대로 데이터 변경이 잦은 컬럼이나 카디널리티(고유값 수)가 낮은 컬럼(성별 등)에는 인덱스 효과가 미미합니다.

</details>

### Card 12: 정규화 ★

**Q: 데이터베이스 정규화의 목적과 1NF~3NF를 설명하시오.**

**키워드 힌트**
```
목적: 데이터 중복 제거, 이상현상 방지
1NF: 원자값만 (중복 컬럼X)
2NF: 부분 함수 종속 제거
3NF: 이행 함수 종속 제거
단점: JOIN 증가 → 비정규화로 트레이드오프
```

<details>
<summary>답안 예시</summary>

정규화는 데이터베이스에서 데이터 중복을 최소화하고 삽입/갱신/삭제 이상현상을 방지하기 위해 테이블을 올바른 구조로 분리하는 과정입니다.

1NF(제1정규형)는 모든 컬럼 값이 더 이상 분리할 수 없는 원자값이어야 합니다. 2NF(제2정규형)는 1NF를 만족하면서, 기본키의 일부에만 종속된 부분 함수 종속을 제거합니다. 3NF(제3정규형)는 2NF를 만족하면서, 기본키가 아닌 컬럼이 다른 비기본키 컬럼에 종속되는 이행 함수 종속을 제거합니다.

정규화를 과도하게 적용하면 테이블이 지나치게 분리되어 JOIN이 많아지고 성능이 저하될 수 있습니다. 이 경우 조회 성능을 위해 의도적으로 중복을 허용하는 비정규화(Denormalization)를 고려하기도 합니다.

</details>

### Card 13: RDBMS vs NoSQL ★★

**Q: RDBMS와 NoSQL의 차이점과 각각 적합한 사용 상황을 설명하시오.**

**키워드 힌트**
```
RDBMS: 스키마 고정 / 관계·JOIN / ACID / 수직 확장(Scale-up)
NoSQL: 스키마 유연 / 수평 확장(Scale-out) / BASE / 대용량
RDBMS: 금융·쇼핑몰 / NoSQL: SNS피드·로그·캐시
```

<details>
<summary>답안 예시</summary>

RDBMS(관계형 데이터베이스)는 테이블 형태의 고정된 스키마를 가지며, 테이블 간 관계(JOIN)를 통해 데이터를 관리합니다. ACID 트랜잭션을 지원하여 데이터 일관성이 높고, 복잡한 쿼리와 트랜잭션이 필요한 금융, 이커머스 등에 적합합니다. 수직 확장(Scale-up) 방식이라 하드웨어 업그레이드로 성능을 높입니다.

NoSQL은 스키마가 유연하여 비정형 데이터를 자유롭게 저장할 수 있습니다. 수평 확장(Scale-out)이 용이하여 대용량 트래픽 처리에 유리합니다. ACID 대신 BASE(Basically Available, Soft state, Eventually consistent)를 따르므로 일관성보다 가용성과 성능을 우선시합니다. 대규모 SNS 피드, 로그 데이터, 캐시, 실시간 추천 등에 적합합니다.

</details>

### Card 14: 시간복잡도 Big-O ★★

**Q: Big-O 표기법이란 무엇이고, 주요 시간복잡도를 빠른 순서로 설명하시오.**

**키워드 힌트**
```
O(1) < O(logN) < O(N) < O(NlogN) < O(N²) < O(2^N)
O(1): 해시 / O(logN): 이분탐색 / O(N): 선형탐색
O(NlogN): 정렬 / O(N²): 이중for / O(2^N): 완전탐색
```

<details>
<summary>답안 예시</summary>

Big-O 표기법은 알고리즘의 시간 복잡도를 나타내는 표기법으로, 입력 크기 N이 커질수록 실행 시간이 얼마나 증가하는지를 최악의 경우 기준으로 나타냅니다.

성능이 빠른 순서는 다음과 같습니다. **O(1)**은 입력 크기와 무관하게 일정한 상수 시간입니다(해시 테이블 조회). **O(log N)**은 매 단계마다 탐색 범위를 절반으로 줄입니다(이분탐색). **O(N)**은 입력에 비례하는 선형 시간입니다(선형탐색). **O(N log N)**은 효율적인 정렬 알고리즘의 복잡도입니다(퀵정렬, 합병정렬). **O(N²)**은 이중 반복문으로 N이 커질수록 급격히 느려집니다(버블정렬). **O(2^N)**은 지수 시간으로, N이 20 이상이면 사실상 사용 불가합니다(완전탐색).

일반적으로 코딩테스트에서 1초에 약 1억 번 연산 가능하다고 가정하며, N의 크기를 보고 허용 가능한 알고리즘을 선택합니다.

</details>

---

### Card 15: 정렬 알고리즘 비교 ★

**Q: 주요 정렬 알고리즘의 시간복잡도와 특징을 비교하시오.**

**키워드 힌트**
```
버블/선택/삽입: O(N²) / 단순
합병: O(NlogN) / 안정정렬 / 추가공간 O(N)
퀵: O(NlogN) 평균, O(N²) 최악 / 빠름 / 불안정
Python sorted(): Timsort (합병+삽입) / O(NlogN) / 안정정렬
```

<details>
<summary>답안 예시</summary>

버블/선택/삽입 정렬은 모두 O(N²) 시간복잡도로 구현이 단순하지만 대용량 데이터에는 부적합합니다. 삽입 정렬은 데이터가 거의 정렬된 경우 O(N)에 가까워 효율적입니다.

합병 정렬(Merge Sort)은 O(N log N)을 보장하며, 같은 값의 순서를 유지하는 안정 정렬(Stable Sort)입니다. 단, 병합 과정에서 O(N)의 추가 메모리가 필요합니다. 퀵 정렬(Quick Sort)은 평균 O(N log N)으로 실제로 가장 빠른 편이지만, 최악의 경우(이미 정렬된 배열에서 피벗을 잘못 선택) O(N²)이 될 수 있으며 불안정 정렬입니다.

Python의 `sorted()`는 Timsort(합병 정렬 + 삽입 정렬의 하이브리드)를 사용하며, O(N log N)을 보장하고 안정 정렬입니다.

</details>

### Card 16: 스택 vs 큐 ★★

**Q: 스택과 큐의 차이점, LIFO/FIFO 개념, 각각의 사용처를 설명하시오.**

**키워드 힌트**
```
스택: LIFO(후입선출) / 뒤로가기·Undo·괄호검사·DFS
큐: FIFO(선입선출) / 대기열·BFS·프린터
Python: 스택=list / 큐=deque (popleft() O(1))
```

<details>
<summary>답안 예시</summary>

스택(Stack)은 LIFO(Last In First Out, 후입선출) 구조로, 마지막에 넣은 데이터가 먼저 나오는 자료구조입니다. 접시를 쌓아두고 가장 위에서부터 가져가는 것과 같습니다. 함수 호출 스택, 브라우저 뒤로가기, 실행취소(Undo), 괄호 유효성 검사, DFS 구현에 활용됩니다.

큐(Queue)는 FIFO(First In First Out, 선입선출) 구조로, 먼저 넣은 데이터가 먼저 나오는 자료구조입니다. 줄을 서서 먼저 온 사람이 먼저 서비스받는 것과 같습니다. 작업 대기열(프린터), 이벤트 처리, BFS 탐색, 메시지 큐에 활용됩니다.

Python에서는 스택을 `list`로 구현하고, 큐는 `collections.deque`를 사용합니다. `list.pop(0)`은 O(N)이지만 `deque.popleft()`는 O(1)이므로 큐에는 반드시 deque를 사용해야 합니다.

</details>

### Card 17: OOP 4원칙 ★★

**Q: 객체지향 프로그래밍(OOP)의 4가지 특성을 설명하시오.**

**키워드 힌트**
```
캡슐화: 내부 숨김, 인터페이스만 공개
상속: 부모 클래스 재사용
다형성: 같은 인터페이스, 다른 구현 (오버라이딩/오버로딩)
추상화: 핵심만 추출, 세부사항 숨김
```

<details>
<summary>답안 예시</summary>

**캡슐화(Encapsulation)**는 객체의 내부 구현을 숨기고 외부에는 필요한 인터페이스만 공개하는 것입니다. 이를 통해 내부 구현이 변경되어도 외부 코드에 영향을 최소화합니다.

**상속(Inheritance)**은 부모 클래스의 속성과 메서드를 자식 클래스가 물려받아 재사용하는 것입니다. 코드 중복을 줄이고 확장성을 높입니다.

**다형성(Polymorphism)**은 같은 인터페이스로 다양한 객체를 동일하게 다룰 수 있는 특성입니다. 메서드 오버라이딩(부모 메서드 재정의)과 오버로딩(같은 이름 다른 파라미터)이 대표적입니다.

**추상화(Abstraction)**는 복잡한 시스템에서 핵심 개념만 추출하고 불필요한 세부사항을 숨기는 것입니다. 추상 클래스나 인터페이스로 공통 동작을 정의합니다.

</details>
