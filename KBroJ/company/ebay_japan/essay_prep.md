## 주제 1: TCP vs UDP ← 데모 문제 유형

### 모범 답안
```
(1) TCP와 UDP의 차이점:

TCP는 연결 지향 프로토콜로, 데이터를 전송하기 전에 3-way handshake를
통해 연결을 먼저 수립합니다. 데이터의 순서를 보장하고 손실된 패킷은
재전송하므로 신뢰성이 높지만, 그만큼 속도가 느립니다.

UDP는 비연결형 프로토콜로, 연결 수립 없이 데이터를 바로 전송합니다.
순서 보장이나 재전송이 없어 신뢰성은 낮지만 속도가 빠릅니다.

(2) TCP를 사용하는 곳:

신뢰성이 중요한 곳에 사용합니다.
- HTTP/HTTPS (웹 통신)
- 파일 전송 (FTP)
- 이메일 (SMTP)
- 데이터베이스 연결

(3) UDP를 사용하는 곳:

빠른 속도가 중요하고 일부 데이터 손실이 허용되는 곳에 사용합니다.
- 실시간 스트리밍 (유튜브, 넷플릭스)
- 온라인 게임
- DNS 조회
- VoIP (인터넷 전화)
```

## 주제 2: HTTP vs HTTPS

### 모범 답안
```
HTTP는 데이터를 암호화하지 않고 평문으로 전송하는 프로토콜입니다.
속도는 빠르지만 중간에 데이터가 탈취될 위험이 있습니다.

HTTPS는 SSL/TLS를 통해 데이터를 암호화하여 전송하는 프로토콜입니다.
암호화로 인해 HTTP보다 약간 느리지만, 데이터 도청과 변조를 방지합니다.

로그인, 결제, 개인정보 처리 등 보안이 중요한 모든 웹 서비스는
HTTPS를 사용합니다. 현재 대부분의 웹사이트는 HTTPS를 기본으로 사용합니다.
```

## 주제 3: REST API

### 모범 답안
```
REST API는 HTTP를 기반으로 자원(Resource)을 URI로 표현하고,
HTTP 메서드로 해당 자원에 대한 행위를 정의하는 API 설계 방식입니다.

주요 HTTP 메서드:
- GET: 자원 조회 (예: GET /users/1 → 1번 유저 정보 조회)
- POST: 자원 생성 (예: POST /users → 새 유저 생성)
- PUT: 자원 전체 수정 (예: PUT /users/1 → 1번 유저 전체 수정)
- PATCH: 자원 일부 수정 (예: PATCH /users/1 → 1번 유저 일부 수정)
- DELETE: 자원 삭제 (예: DELETE /users/1 → 1번 유저 삭제)

REST API의 특징은 무상태성(Stateless)으로, 서버가 클라이언트의 상태를
저장하지 않아 확장성이 좋습니다.
```

## 주제 4: 프로세스 vs 스레드

### 모범 답안
```
프로세스는 운영체제로부터 독립적인 메모리 공간을 할당받아 실행되는
프로그램의 단위입니다. 각 프로세스는 독립된 메모리를 사용하므로
한 프로세스의 오류가 다른 프로세스에 영향을 주지 않습니다.

스레드는 프로세스 내에서 실행되는 더 작은 실행 단위입니다.
같은 프로세스의 스레드들은 메모리(힙, 코드, 데이터)를 공유합니다.
메모리를 공유하므로 통신이 빠르고 생성 비용이 낮지만,
동기화 문제(Race Condition)가 발생할 수 있습니다.

정리:
- 프로세스: 독립 메모리, 안전하지만 무거움
- 스레드: 메모리 공유, 빠르고 가볍지만 동기화 필요
```

## 주제 5: 데이터베이스 인덱스

### 모범 답안
```
인덱스는 데이터베이스에서 특정 컬럼의 검색 속도를 높이기 위한
자료구조입니다. 책의 목차와 같은 역할을 합니다.

장점:
- SELECT 쿼리 성능이 크게 향상됩니다. (O(N) → O(log N))

단점:
- INSERT, UPDATE, DELETE 시 인덱스도 함께 수정되므로 느려집니다.
- 인덱스를 저장하기 위한 추가 저장 공간이 필요합니다.

따라서 조회가 잦고 수정이 적은 컬럼에 인덱스를 적용하는 것이 적합합니다.
예: 사용자 ID, 이메일, 생성일 등
```

## 주제 6: 트랜잭션과 ACID

### 모범 답안
```
트랜잭션은 데이터베이스에서 하나의 논리적 작업 단위입니다.
예를 들어 A가 B에게 돈을 이체할 때, "A 잔고 감소"와 "B 잔고 증가"는
하나의 트랜잭션으로 처리되어야 합니다.

트랜잭션의 4가지 특성(ACID):

- Atomicity(원자성): 트랜잭션의 모든 작업이 전부 성공하거나
  전부 실패해야 합니다. (A 잔고만 줄고 B 잔고가 안 늘어나는 상황 방지)

- Consistency(일관성): 트랜잭션 전후로 데이터베이스의 무결성이
  유지되어야 합니다.

- Isolation(격리성): 동시에 실행되는 트랜잭션들이 서로 영향을
  주지 않아야 합니다.

- Durability(지속성): 커밋된 트랜잭션의 결과는 영구적으로
  반영되어야 합니다.
```

## 주제 7: 스택 vs 큐

### 모범 답안
```
스택(Stack)은 LIFO(Last In First Out) 구조로, 마지막에 넣은 데이터가
먼저 나오는 자료구조입니다.
사용처: 함수 호출 스택, 브라우저 뒤로가기, 괄호 검사, 실행취소(Undo)

큐(Queue)는 FIFO(First In First Out) 구조로, 먼저 넣은 데이터가
먼저 나오는 자료구조입니다.
사용처: 작업 대기열(프린터), 이벤트 처리, BFS 탐색, 메시지 큐

예시로 비교하면,
스택은 식판을 쌓아두고 가장 위에서부터 가져가는 것과 같고,
큐는 줄을 서서 먼저 온 사람이 먼저 서비스받는 것과 같습니다.
```
