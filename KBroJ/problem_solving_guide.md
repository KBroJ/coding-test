# 코딩테스트 문제 풀이 가이드

---

## 문제 풀이 순서

```
1. 문제 읽기       → 뭘 구해야 하는지 파악
2. 입출력 확인     → 입력 형식, 출력 형식
3. 제약 조건 확인  → N의 크기 → 알고리즘 선택
4. 유형 분류       → 어떤 방식으로 풀지
5. 생각하기 작성   → 코딩 전에 로직 먼저 정리
6. 구현
7. 예제 테스트     → 손으로 먼저 직접 돌려보기
8. 제출
```

---

## STEP 3. 제약 조건으로 알고리즘 선택

N의 크기가 허용하는 시간복잡도를 알려줘요.
코테는 보통 1초 안에 약 1억 번 연산이 가능해요.

| N 크기 | 허용 시간복잡도 | 사용 가능한 방법 |
|--------|--------------|----------------|
| N ≤ 10 | 제한 없음 | 완전탐색, 이중 for문 다 OK |
| N ≤ 1,000 | O(N²) 이하 | 이중 for문 OK |
| N ≤ 100,000 | O(N log N) 이하 | 정렬, 이분탐색 |
| N ≤ 1,000,000 | O(N) 이하 | 선형탐색, DP |

### 예시
- 20299 (N ≤ 500,000) → 이중 for문 불가 → 선형탐색 O(N) 사용
- 16503 (경우의 수 2가지) → 완전탐색 OK

---

## STEP 4. 유형 분류

문제 읽고 아래 질문을 순서대로 해봐요.

---

### A. 완전탐색 / 브루트포스

> "가능한 경우를 다 해봐도 될 만큼 작아?"

- 경우의 수가 작을 때 (N ≤ 1,000 정도)
- "모든 경우를 시도해서 조건 만족하는 거 찾기"

**패턴**
```python
for i in range(1, N+1):
    if 조건:
        정답 저장
        break
```

**풀었던 문제**
- 16503: 연산 순서가 딱 2가지 → 두 경우 다 계산
- 15995: a* = 1부터 하나씩 시도해서 조건 만족하는 첫 수 찾기

---

### B. 선형탐색

> "처음부터 끝까지 한 번 훑으면서 조건 체크하면 돼?"

- N개 데이터를 순서대로 보면서 조건 판단
- 정렬 필요 없고, 각 데이터가 독립적일 때

**패턴**
```python
result = 초기값
for i in range(N):
    if 조건:
        result 갱신
```

**풀었던 문제**
- 20299: 팀마다 L >= 조건, S 합산 조건 독립적으로 체크
- 20124: N명 훑으면서 최고점자 추적

---

### C. 정렬

> "순서를 맞추면 비교나 탐색이 쉬워져?"

- 두 배열의 구성이 같은지 비교할 때
- 가장 크거나 작은 값을 찾을 때
- 순서가 중요한 문제

**패턴**
```python
arr.sort()                    # 오름차순
arr.sort(reverse=True)        # 내림차순
sorted_arr = sorted(arr)      # 원본 유지
```

**풀었던 문제**
- 18766: 카드 구성 비교 → 정렬 후 == 비교
- 33846: 삽입 정렬 구현

---

### D. 문자열 처리

> "문자를 쪼개고, 붙이고, 변환하는 게 핵심이야?"

- 입력이 문자열이거나 문자 단위로 처리해야 할 때
- 특정 문자 기준으로 분리/결합
- 대소문자 변환, 역순, 포함 여부

**자주 쓰는 패턴**
```python
s[::-1]             # 문자열 역순
s.split("_")        # 특정 문자로 분리
"_".join(words)     # 리스트를 문자열로 합치기
s.lower()           # 소문자 변환
s.upper()           # 대문자 변환
ch.isupper()        # 대문자인지 확인
```

**풀었던 문제**
- 32401: 회문 판별 (역순 비교)
- 1259: 팰린드롬수 ([::-1] 역순 비교)
- 16205: 카멜/스네이크/파스칼 표기법 변환

---

### E. 수학 계산

> "반복 없이 공식으로 바로 답이 나와?"

- 규칙이 있고 수식으로 표현 가능할 때
- 반복 횟수가 정해진 계산

**자주 쓰는 패턴**
```python
import math
math.ceil(x / y)              # 올림 나눗셈
(x + y - 1) // y              # 올림 나눗셈 (import 없이)
```

**풀었던 문제**
- 33753: 초과 시간 계산 후 올림 처리
- 24264: 이중 for문 실행 횟수 → n²

---

### F. DP (동적 프로그래밍)

> "같은 계산이 반복돼? 이전 결과를 저장해서 재사용할 수 있어?"

- 큰 문제를 작은 문제로 나눌 수 있을 때
- 점화식을 세울 수 있을 때 (f(n) = f(n-1) + f(n-2) 같은 형태)

**패턴**
```python
dp = [0] * (N+1)
dp[0] = 초기값
dp[1] = 초기값
for i in range(2, N+1):
    dp[i] = dp[i-1] + dp[i-2]   # 점화식
```

**풀었던 문제**
- 2748: 피보나치 수 (dp[n] = dp[n-1] + dp[n-2])

## 유형 분류 체크리스트

```
문제 읽고 순서대로 체크해봐요!

□ 경우의 수가 적어서 다 해봐도 돼?          → 완전탐색
□ N개를 하나씩 보면서 조건 체크하면 돼?      → 선형탐색
□ 정렬하면 풀려?                            → 정렬
□ 문자/숫자 쪼개고 붙이는 게 핵심이야?       → 문자열 처리
□ 공식으로 바로 답이 나와?                  → 수학 계산
□ 이전 결과를 저장해서 재사용할 수 있어?     → DP
```
